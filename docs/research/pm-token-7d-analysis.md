## 1. 核心结论

**直接回答：PM 根治（`#331` 第 0–6 期）落地后，PM 的单位操作效率确实有显著优化，但整体 token 消耗被两大未治理的结构性问题抵消了一半以上。**

在剥离“PM 运行时从 Claude Code 切到 Antigravity (`agy`)”与“每日任务量波动”两个混淆变量，**严格控制为同一运行时与模型（`agy / gemini-4-neon-medium`）** 对比 `#331` 落地前（11-23 11:13 ～ 11-25 23:44）与落地期及之后（11-25 23:45 ～ 11-28 01:29）：

- **明确下降的维度（根治生效）**：
  - **单轮 API 往返数（`Req/Turn`）下降 30.4%**：从 `3.09` 降至 `2.15`（用户轮 `4.06 → 2.74`，`deliver` 轮 `2.34 → 1.85`；P0–P5 收官后的老化会话稳态低至 **`1.96`**）。
  - **单轮工具调用与前台重活下降 47.9%**：从 `2.61` 降至 `1.36` 次工具/轮；前台写文件（逐字写任务书等）降 **72.5%**；`>=5 req` 重型前台轮的 token 占比从 **23.8%** 降至 **3.9%～7.6%**。
  - **单位产出消耗下降 35%～45%**：每完成 1 个任务的 PM 消耗从 `9.7 reqs / 2.30M tok / $0.74` 降至 **`6.1 reqs / 1.48M tok（-35.7%）/ $0.41（-45.3%）`**；每 10 条 wake 事件消耗下降 **34.2%**。
  - **稳定性噪音归零**：`agy` PM API 报错从 `10` 次降至 `0` 次；监督器日志（163 轮）中超 120s 硬预算仅 `2` 轮（1.2%），无误轮换。
- **未降甚至反升的维度（最大失血点）**：
  - **单次请求上下文体积未降反弹**：`pm-settings.json` 中的 `autoCompactWindow: 200k` / 空闲 `150k` 预压仅对 Claude Code 生效（Claude 会话在 917 次请求中自动压缩 6 次，均值稳在 **115k/req**）。切至 `agy` 且废除 200k 自动轮换后，会话单调膨胀：`#331` P0–P5 全部落地后的 11-27 仍涨至 **369.9k/req**（峰值 **404.5k**，0 次压缩），与根治前 11-24 的 **372.6k/req** 基本持平。
  - **`deliver` 高频单事件唤醒占比反升**：单事件批次仍占 **94.9%**，`deliver` 占 `agy` PM 总 token 比重从 **46.9%** 升至 **62.9%**；其中 **25.6%** 是 0 工具、1 请求的纯回执唤醒（典型如 `land` helper 引发 task `done` + helper `done` 双重唤醒）。
  - **长上下文叠加空闲缓存 TTL 过期**：全周仅 `17` 次 `>150k` 缓存未命中请求（占 `agy` 请求数 `1.7%`）就烧掉 **$13.17（占 `agy` PM 总费用的 18.6%）**；单次 376k 空闲后首条请求可花掉 `$0.75`。

## 4. 下一步 PM 省 Token 优化建议（按预期节省排序）

以下收益基于近 7 天真实 `agy` PM 请求流反事实回放（已计入每次压缩/轮换约 `300k–400k tok / $0.25–$0.30` 的重置开销）：

1. **【P0，预计省 `agy` PM 52%～60% token / 43%～51% 费用】为 `agy` PM 补齐 150k～165k 空闲压缩或无感软轮换**
   - **依据**：Post-#331 阶段 `>165k` 的超额上下文占总 token 的 **38.3%**；叠加 150k 以上空闲缓存 TTL 过期重算（占 `agy` PM 总费用的 **18.6%**），把上下文锁回 150k–165k 内可同时砍掉 cache_read 膨胀与冷重算尖峰。
   - **做法**：监督器检测到 `agy` PM 空闲且最新 `prompt_tokens >= 150k`（或硬阈值 `180k`）时自动触发压缩或 `pm.py rotate --reason context_budget`（实测单次交接仅 `$0.20`）；若空闲已超缓存 TTL（15–30 分钟）且上下文 `>=150k`，优先软轮换而非唤醒旧肥上下文。

2. **【P1，预计省 Post-#331 PM 10%～16% token / 8%～13% 费用】治理 `deliver` 单事件高频唤醒与纯回执噪音**
   - **依据**：`deliver` 已占 `#331` 后 `agy` PM 的 **62.9%** token，其中 **25.6%**（30 轮）为 0 工具、1 请求纯回执；每次 `land` helper 还会先后触发“任务 `done`”与“helper `done`”双重唤醒。
   - **做法**：① 合并 `land` helper 的任务完成与退出通知（`helper done` 默认不单独唤醒）；② 无阻塞、无下游依赖解锁的 `done` 或已自动派审的 `review` 降级为静默台账写入；③ 对非 `blocked`/非用户消息的 `deliver` 增加 `20–30s` 防抖聚合窗。

3. **【P2，预计省 `agy` PM ~6% 费用】禁止在 `>100k` 上下文内热切模型**
   - **依据**：单次在 282k 上下文内切 `claude-opus-5-5-medium` 导致 3 次缓存全失效，仅 10 条请求多花 `$4.56`（占全周 `agy` PM 费用的 `6.4%`）。
   - **做法**：切换模型族时统一走 `pm.py rotate --profile <target>` 带紧凑交接书（~15k）重启，避免异构长历史引发全量 uncached input 账单尖峰。

4. **【P3，预计省 `agy` PM 5%～9% token 与费用】固化“薄派活”上限，压缩残留重型前台轮**
   - **依据**：全周 `agy` 仍有 `31` 个 `>=5 req` 重型轮（超出 3 步的 `134` 次往返消耗 `22.2M tok / $6.34`）；`#331` 后仍有 `7.1%` 轮次达 `>=5 req`。
   - **做法**：将 `[Occupation hint]` 从单一耗时阈值扩展到步数阈值（如 `steps >= 4`），引导 PM 对多文件排查与长文档撰写一律交给 worker 或只读 helper。

5. **【P4，可靠性 + 间接收益】修复 `agy` 终端 W6 注入未启动；若回切 Claude PM 则屏蔽后台 Bash 逐条通知**
   - **依据**：W6 在 24 小时内触发 2 次并引发 15 分钟卡单；若未来切回 Claude Code 做 PM，将后台长命令收敛至 `pm.py helper` 可直接消除 12.5% 的 `<task-notification>` 唤醒开销。
