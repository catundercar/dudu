# UI 设计调研与第一性原理重设计（ui-design-research）

> 专注两件事：**① 从 X（Twitter）高效获取顶级设计师的一手设计思路；② 从第一性原理诊断现状并产出 2–3 套有明确取舍的差异化方案（配真实内容视觉对比稿）。**
> 通用方法论，不绑定特定前端框架、设计风格或单一产品。默认只做调研与方案出稿，**不擅自改生产代码**，待决策者选型或混搭拍板后再进入实现。

---

## 工作流总览（5 步闭环）

### 第 1 步 · 拆解现状与采集真实内容

1. **读图与读现状**：若有用户截图或现有界面，逐一记录每个痛点的位置、占位高度、层级关系与交互路径；**先看用户在这屏要完成的核心任务，不急着想“怎么修旧组件”**。
2. **采集真实内容样本**：从当前产品抽取真实数据（长标题、中英混排、密集列表、嵌套层级、长段正文、边界/溢出状态）。后续视觉对比稿**禁止用 `Lorem ipsum` 或理想化短英文**。
3. **提炼 2–4 个精确设计问题词**：把模糊的“不好看/太乱”转译为可检索的专业词，例如：`chrome reduction`、`tonal layering`、`segmented control`、`concentric border radius`、`sidebar hierarchy`、`hover intent`、`optical alignment`、`disclosure / progressive search`。

### 第 2 步 · 在 X（Twitter）系统检索一手设计思路

详细检索词、标杆设计师索引与提炼模板见 [references/x-research-playbook.md](references/x-research-playbook.md)。

1. **定向检索一手来源**：围绕第 1 步的问题词，在 X（Twitter）检索一线 UI/产品设计师与标杆团队的公开分享（如枯白 Kubai、Rauno Freiberg、Emil Kowalski、Paco Coursey，以及 Linear、Raycast、Arc/Dia、Cursor、Zed、Vercel、Stripe 等设计实践），并顺藤摸瓜核验其个人站、开源组件源码或设计笔记。
2. **反编造铁律**：
   - 只引用**本次实际搜到并阅读过**的公开帖子、文章、样式规则或可观察的产品行为；
   - 严禁凭记忆编造链接、语录或参数；搜不到就换词扩大检索，仍无则如实标明；
   - 清晰区分“作者一手原述”与“基于观察的归纳”。
3. **去滤镜提炼可迁移原理**：X 上许多概念图只在“3 个短词 + 完美留白”下成立。每条案例都必须抽离皮肤，落成**设计原理 + 对应反模式 + 对当前问题的迁移点**。

### 第 3 步 · 第一性原理 UI 诊断（严禁预设“最小改动”）

完整 6 维诊断表与 AI slop 清单见 [references/first-principles-diagnosis.md](references/first-principles-diagnosis.md)。

忘掉现有 DOM / 布局的历史包袱，按六个维度逐一追问根因：
1. **信息架构与主视线**：这一屏的核心决策是什么？哪些二级诊断信息（路径、内部 ID、低频统计）挤占了主扫描线？
2. **Chrome 预算**：导航栏、标签栏、工具条、搜索框是否叠成多层“Chrome 叠罗汉”？有没有功能重复的按钮、未溢出却常驻的控件、或本可默认收起/隐藏的低频区块？
3. **视觉通道与层次**：是否靠到处画边框/套娃卡片分区，而没用好明度阶梯、留白密度（组内间距 < 组间间距）、字重与对齐基准线？
4. **结构去重与 AI Slop 清查**：是否在缩进/位置/图标已经表达含义后，又用多余符号或泛化词重复说一遍？是否存在典型 AI 生成感（重描边套框、圆角加粗左竖条高亮、随手拍的圆角/间距、全宽大块文字按钮堆砌）？
5. **交互成本与反馈**：高频动作是否直达？操作是否优先用克制图标 + 悬停反馈表达而非文字按钮？浮层/悬停卡片是否防闪烁且不遮挡主内容？
6. **边界压力**：长文案、多语言、深层级、宽/窄视口、暗/亮主题下，当前结构哪里会崩？

### 第 4 步 · 产出 2–3 套真正差异化的方案（A / B / C）

1. **差异在结构与取舍，不在换皮肤**：每套方案必须代表一种清晰的设计取向（例如：极简无框排版索引 vs 微表面分组层叠 vs 强焦点按需折叠），写明**美学母体、结构变化、收益、代价与适用偏好**。
2. **全状态覆盖 + 目标技术栈核查**：
   - 同时覆盖关键态（如列表态 vs 详情态、展开 vs 收起、宽屏 vs 窄屏、暗/亮主题）；
   - 对照当前项目的真实渲染技术栈（Web CSS / 原生桌面 / 移动端 / 自定义 UI 引擎）核查每项手法的可实现性，标出限制与替代写法，**不画实现不了的空气效果**。
3. **给出默认推荐 + 可自由混搭项**：标明 1 套综合最稳健的推荐方案，并明确列出可独立替换的子模块（如“整体选 B，但搜索采用 C 的折叠入口”），帮决策者一步拍板。

### 第 5 步 · 制作真实内容高清视觉对比稿并自检

1. **真实内容并排对比**：用第 1 步采集的真实数据，将 2–3 套方案并排渲染到同一张高分辨率对比图（建议 2× Retina），包含标题、设计取向摘要、关键态特写与真实数据来源标注。
2. **后台静默出图，不干扰前台**：根据环境选择高精矢量（SVG → 2× PNG）或无头浏览器后台渲染 HTML 截屏；出图后**必须亲自逐区看图自检**（无文字重叠/异常裁切、圆角与基线对齐、明暗对比清晰、真实数据无失真），有瑕疵立刻重出。

## 标准交付物

1. **调研与方案对比报告（Markdown）**：现状第一性原理诊断 → X 一手调研来源与原理提炼 → 2–3 套差异化方案对比表 → 目标技术栈可实现性核查 → 推荐结论与可混搭选型项。
2. **2× 高清真实内容视觉对比图（PNG）**（及可复现生成脚本/HTML）。
