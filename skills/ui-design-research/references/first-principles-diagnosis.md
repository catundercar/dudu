# 第一性原理 UI 诊断、差异化方案产出与真实内容对比稿手册

---

## 1. 第一性原理 6 维 UI 诊断框架

拿到现状截图或界面时，**不要从“现有组件怎么微调”出发**，而是先抛开实现，按以下 6 个维度找出根因：

| 维度 | 核心追问 | 常见病灶信号 |
| :--- | :--- | :--- |
| **1. 任务焦点与 IA** | 用户打开这一屏的 Top 1–2 决策是什么？第一眼看到的是核心内容还是噪音？ | 内部 ID / 冗长路径 / 技术字段抢占主标题位；重要待办与低优先级信息视觉权重相同 |
| **2. Chrome 预算** | 顶栏、标签栏、分段栏、搜索栏、侧栏一共吃掉了多少有效画布？ | 多行导航“叠罗汉”；同一功能存在两个入口（如侧栏开关 + 面板关闭 `×`）；未溢出时常驻下拉计数；低频区块默认常驻占位 |
| **3. 视觉通道与层次** | 区域归属是用克制的明度/留白/对齐表达，还是靠到处画框硬隔开？ | 3–4 层平行 `1px` 闭合边框套娃；组内间距与组间间距不分，看不出谁和谁是一组；无固定扫描基准线 |
| **4. 结构去重与 AI Slop** | 是否存在用文案/符号重复表达结构已经说清的事？是否有廉价模板感？ | 见下方《AI Slop 自查表》 |
| **5. 交互成本与反馈** | 高频操作是否 1 步直达？操作表达是否克制？浮层/悬停是否稳重？ | 满屏大号带框文字按钮；无宽限期的悬停弹窗一划过就乱闪；返回/关闭层级不清晰 |
| **6. 真实边界压力** | 换成真实生产数据后，这套布局还能保持体面吗？ | 标题一长就撞右侧状态标；窄屏/分屏下控件挤压折行；亮/暗主题或中/英切换后对比度崩坏 |

### AI Slop 快速自查表（命中 2 条以上即需结构重设计）
- **框中画框**：每个区块都自带外描边 + 圆角 + 独立底色，形成“后台表单线框图”。
- **圆角 + 加粗左竖条高亮**：给圆角卡片/列表行加 `2–4px` 彩色左侧竖条，视觉呈括号状弯弧且极为廉价（选中态应改用克制底色、字重或图标状态）。
- **语义重复**：已经缩进在父项下方，还要画 `↳` 箭头并写泛化角色词；已有状态色点，又在旁边挂大块同义文字徽章。
- **失配圆角与随机间距**：相邻嵌套容器圆角不满足 $r_{\text{inner}} = R_{\text{outer}} - \text{padding}$；间距 5/7/9/11px 混用无栅格秩序。
- **全宽空洞胶囊**：把仅 2–4 个短标签的分段控件拉成 500px+ 通栏条，中间大片空白。
- **文字按钮泛滥**：工具栏或列表行放一排带框文字按钮，而非清晰的矢量图标 + 悬停提示。

## 2. 构思 2–3 套真正差异化的方案（A / B / C）

避免产出“同一布局换三种颜色”的伪选项。围绕当前界面的核心矛盾，沿**结构取舍轴**拉开 2–3 个清晰流派：

- **取舍轴示例**：
  - **信息组织轴**：无框纯排版索引（极简留白） vs 微表面同心层叠分组（体块清晰） vs 强焦点浮起卡（动静强反差）。
  - **Chrome 收放轴**：顶栏合并单行（常驻但压缩高度） vs 按需展开/折叠抽屉（极致画布空间） vs 导航与上下文一体化（消除多行割裂）。
  - **密度轴**：紧凑单行高扫读效率 vs 分层摘要高可读性。
- **每套方案必须交代清楚**：
  1. **美学母体与核心判断**（一句话说清这套方案信什么）；
  2. **关键结构改动**（具体合并/隐藏/重排了哪些区域，省下多少高度/视觉噪点）；
  3. **多态表现**（列表态 vs 详情态、展开 vs 收起、宽屏 vs 窄屏、暗/亮与多语言）；
  4. **明确代价与适用人群**（不藏短板，例如“搜索多一步点击，换取常态首屏多露 3 条内容”）。
- **降低决策摩擦**：
  - 标出 **1 套推荐方案** 并说明综合理由；
  - 结尾单列 **可自由混搭子项**（让决策者可以说“整体 B + 方案 C 的侧栏收起入口”）。
- **技术栈可实现性核查**：
  - 对照目标项目真实的渲染技术与 API 文档，逐项列出“设计要素 → 落地机制 → 限制/降级策略”，确保没有不可落地的纯概念装饰。

## 3. 真实内容高清视觉对比稿通用方法

### 3.1 真实内容硬约束
1. **绝不造理想短数据**：从目标产品真实数据中采样代表性记录（最长与中等标题、多语言混排、真实数字精度、真实嵌套与空态），在对比图底部注明数据出处。
2. **同等内容横向拉齐**：A / B / C 三套方案必须填充**完全相同的一组真实数据**，让决策者一眼看出不同结构对信息密度、呼吸感与扫描效率的真实影响。

### 3.2 对比画布构图规范
- **画布尺寸**：横向并排 2–3 栏（典型逻辑画布 `1600–1920px` 宽，导出 **2× Retina PNG**，清晰到可 100% 放大检视字形与 1px 细节）。
- **画布结构**：
  - **顶部抬头**：标题 + 一行调研来源摘要 + 交互态图例（如选中态/展开态含义）；
  - **主对比区**：A / B / C 等宽并排，每栏顶部配方案标签、美学流派名、一句话核心取舍（推荐方案加轻标识）；
  - **底部特写区（按需）**：并排补全关键次态（如详情态头部、悬停详情卡、收起/展开入口或窄屏退化效果）；
  - **底部脚注**：真实数据来源说明。
- **渲染方式选择（后台静默，不抢前台焦点）**：
  - **矢量精确对照**：脚本生成内嵌系统字体（如 `PingFang SC` / `SF Pro` / `Inter` / `SF Mono`）的高精 SVG，经矢量光栅化工具（如 `rsvg-convert -z 2`）导出 2× PNG。
  - **HTML/CSS 真实排版**：编写独立静态 HTML，用隔离后台无头浏览器（如浏览器 MCP 后台上下文，避免破坏用户正在使用的桌面浏览器）按 2× DPR 整页截屏。
- **交付前必做视觉自检**：亲自打开生成的 PNG 逐栏检查——有无文字截断撞车、基线偏移、圆角错位、对比度不足或伪造数据；有瑕疵即刻修复重渲染。
